# App Overview

## What it does

A guided home-organizing app: pick rooms → take guided photos → AI (Gemini) detects specific areas/objects that need attention → measure the space → talk through goals with Natasha (an AI interior-decorator persona) → get a personalized recommendation + a shopping list pulled only from a pre-approved Amazon catalog → repeat for other areas/rooms → generate a final PDF report.

## Shipped this sprint

- **Real accounts** — email/password signup and login (`/auth/signup`, `/auth/login`), checked against bcrypt-hashed passwords in Postgres, not a stub. JWT-based session tokens stored on-device so the app doesn't force a re-login every launch.
- **Resumable progress** — projects are now tied to a logged-in user and stored in Railway Postgres instead of an anonymous local SQLite blob. Reopening the app after closing it (or on a new device) offers "Continue your project" if one is in progress, restoring which rooms are already organized. (Scope boundary: this restores at the room level, not exact mid-step state like an in-progress photo upload — see TBD.)
- **Natasha's guided chat** — the old single free-text question per area is now a short (≤5 question) adaptive conversation, seeded with Natasha's overview of what she sees in the photos, piggybacking off prior answers, and stopping as soon as she has enough context. Includes guardrails: off-topic input is discarded (not stored) with `"Sorry, please stay within the topic of organization."`; chatbot-style small talk gets `"Sorry I am not a chatbot, I can only take in context to make your organizing more personalized."` Natasha also names the gap when a user's goal is ambiguous (e.g. "make it tidy" with no sense of style) instead of guessing silently.
- **Voice tiers** — paid tier uses Natasha's persona; free tier uses a neutral assistant voice with the same organizing knowledge base. Both are functionally identical right now (see TBD) — only the tone differs.
- **Dynamic + optional photos** — after the first guided photo set for an area, Gemini can request 1-2 specific additional angles if it judges the photos insufficient (shown as extra guided slots). A fully optional "add more photos" section (pick a photo → describe it → repeat, add/remove freely) is available on every photo screen. Minimum photos required raised from 1 to 2, with the requested copy: *"1 image won't provide enough context for the AI to create a good plan, please upload more."*
- **Object-aware measurements + fixed back button** — the measurement wizard now asks the right fields per object type (a table gets Length/Width/Height, not "depth"; a rug gets Length/Width only; a closet/cabinet/shelf gets an outside pass *and* a separate inside-clearance pass for fitting bins) instead of one generic width/depth/height/count set for everything. The screen never rendered a Back button at all before — it's now wired through every step, including the shelf-count step.
- **Room flow fix** — "Organize Another Room" is now hidden while items remain in the current room, so users finish one room before being offered the next. "Skip to Final Report" stays available at any point, so nothing is forced.
- **Combination shopping list** — product matching now looks for a *combination* of catalog items that sum to the measured space (e.g. two 25" boxes for a 50" shelf) before falling back to a single best-fit item, and only ever recommends items from the pre-approved catalog — never invented outside products.
- **PDF download fixed** — the generator was crashing on ordinary punctuation (quotes, ampersands, angle brackets) because report text wasn't escaped before being fed into ReportLab's markup parser. Fixed, plus `reportlab` is now actually pinned in `requirements.txt` (it was used but missing before) and generated PDFs are cleaned up after 7 days instead of accumulating forever.
- **"Timeout / healthcheck failed" / ngrok** — investigated and found already fixed in the existing code (ngrok fully removed, CORS+threading bug already patched). No further change needed; if you still see this, it's worth re-verifying against a fresh `git pull` rather than a stale build.
- **Security** — `backend/.env` was accidentally committed to git history; it's now untracked going forward (still gitignored, kept locally). **Rotate the Gemini API key and the Railway Postgres password** since both were exposed in history/chat before this fix.

## Shipped this round (post-testing fixes)

- **Fixed: PDF download crash on SDK 54** — `expo-file-system`'s `downloadAsync` was removed in favor of a new File/Directory API; now imports from `/legacy`, same behavior restored.
- **Fixed: Amazon links wouldn't open** — `Linking.canOpenURL()` is unreliable inside Expo Go for perfectly valid https links; now calls `openURL` directly.
- **Fixed: wrong/mismatched product recommendations** — two real bugs: a combination-matching bug mislabeled mixed-product results (e.g. showed "2×" on two *different* products when only one of each was wanted — now correctly prefers N-of-the-same-item); and product images were guessed Unsplash stock photos with no way to verify what they actually showed (how a bathroom photo ended up on a "drawer organizer") — replaced with plain category icons until real product photography exists.
- **Fixed: recommended products with no real connection to the plan** — product matching was purely dimensional (does it physically fit) with zero check against what the recommendation text or the user's stated goal actually call for. A second AI pass now drops any product that doesn't genuinely match the plan, even if it fits — an empty shopping list is now a valid, correct outcome instead of always forcing a pick.
- **Fixed: chatbot echoing your answers back verbatim** — strengthened the prompt with an explicit rule against repeating the user's message.
- **Fixed: "unauthorized to modify this project" on Save** — a systemic bug: every screen called the backend with plain `fetch()`, and only `App.js`'s axios calls ever attached the login token (axios and fetch are separate clients — the axios default header never applied to fetch calls). The moment any endpoint started checking ownership, every save/load from a screen failed silently-ish with "unauthorized." New shared `frontend/api.js` (`apiFetch`) wraps every backend call app-wide with the current token, kept in sync by `App.js` on login/logout.
- **Fixed: Recommendations screen crash** and **chat's question-cap not counting guardrail turns** (a user spamming off-topic messages could loop the chat forever).
- **Terminology**: replaced "depth" everywhere (backend prompts, frontend labels, error copy) with **length/width/height** (+ inside variants) — clearer and matches how people actually describe furniture dimensions.
- **Removed** the "Add All to Amazon Cart" button (storefront-level, not per-product — not useful until real per-product links exist, see TBD).
- **Projects tab** — a slim two-tab strip (Home / Projects) once logged in, per direction to keep navigation minimal. Projects lists every project you've started, tap an in-progress one to resume or a finished one to reopen its report. Reopening an already-completed project's report now reuses the cached text instead of burning a fresh Gemini call every time (PDF is still cheaply regenerated if the retention cleanup already removed the file).
- **Chat speed investigated** — timed real calls: 2.3–3.9s per exchange, hitting Gemini directly with no added overhead from the code. That's normal single-call AI latency, not a bug — no redundant calls found. Loading copy now switches to a reassurance line ("Still thinking it through...") past ~2.5s instead of just sitting on "typing..." indefinitely.

## Shipped this round (object-aware measurements, onboarding, captcha, email)

- **Measurement flow reordered + interior-aware** — close-up photos (`AreaPhotoScreen`) now run *before* measuring (`MeasureSpaceScreen`), because judging whether an object has an interior worth measuring requires actually seeing it first: `ItemSelectionScreen` → Area Photos → Measure Space → chat. A new single-call endpoint, `POST /area/measurement-plan`, looks at those photos and decides `has_interior`, visually counts shelves/compartments with a `count_confidence` flag, and returns which dimension fields are relevant — replacing the old text-only `/area/measurement-fields`.
  - A real, stored `PRIORITY_INTERIOR_OBJECTS` list (closet, cabinet, cupboard, drawer) is baked into the prompt as named anchors, so common cases get a fast, consistent "yes" without the AI re-deriving it from scratch each time — while the same prompt explicitly tells it to generalize the identical reasoning to anything visually similar (pantry, bookshelf, armoire, dresser/nightstand with a drawer, etc.) even though it isn't listed.
  - High-confidence count → "We see **N** — is that right?" with an editable stepper before moving into measurement entry, primed with that count.
  - Low-confidence count → two explicit choices, not one forced path: **"📷 Add More Photos"** (routes back to Area Photos, which round-trips existing photos so nothing is lost) or **"✏️ I'll Tell You"** (manual count entry).
  - No interior detected → the existing outer L/W/H entry stays available but is now explicitly framed as optional ("want to add its overall size anyway? Totally optional"), with Skip as a first-class button.
- **Onboarding screen** — a short, one-time screen introducing Home Free Organizing (founded 2009, Saskatoon, founder Natasha Solvason — a Trained Professional Organizer) shown right after signup only, before the usual consent flow. Returning logins skip straight past it; there's no separate "view again" entry point yet (flagged below).
- **Real invisible captcha (Cloudflare Turnstile)** — both signup and login now run a Turnstile "interaction-only" challenge before submitting. It's a web widget, not a native RN component, so it runs inside a small bundled HTML page in a `react-native-webview` (`components/CaptchaChallenge.js`); most real users never see it — a checkbox only renders if Cloudflare's servers can't score the request confidently. Backend verifies the token server-side against Cloudflare's `siteverify` endpoint on both `/auth/signup` and `/auth/login`; if `TURNSTILE_SECRET_KEY` isn't configured, verification is skipped with a warning (dev-mode fallback — see README).
- **Pre-photo guidance copy** — a short callout now appears on the first photo screen before capture starts: *"The quality of your plan starts here — clear, well-lit photos give Natasha what she needs to build a plan worth following."*
- **Email the final report** — a new "📧 Email Report" button on the final report screen (defaults to the logged-in user's email, editable) hits `POST /report/email`, which reuses the same report-caching logic as PDF generation (no wasted Gemini call) and sends the PDF as an attachment via plain Gmail SMTP. Exact copy as specified: subject `"Your organization plan is ready"`, body `"Please see attached PDF"`.
- **Real 51-item product catalog + semantic AI matching** — the placeholder catalog (~20 fake products, 5 storefront-level affiliate links) is replaced with a real 51-product catalog built from an actual Amazon spreadsheet (real names, ASINs, and dimensions as given — nothing fabricated). The old 3-bucket category system (kitchen/bathroom/closet, everything else defaulting to "closet") is gone entirely — `select_matching_products` now shows the AI the *whole* catalog at once (real dims, or an adjustable/no-fixed-size note for the ~17 products that don't have one) alongside the area's actual plan and the user's own stated goal, and it picks what genuinely belongs in one pass, with a per-pick reason grounded in that specific plan instead of a canned blurb. Two identically-labeled "Under sink organizer" rows were disambiguated as (Wide)/(Slim) by their real size; adjustable/expandable products (utensil organizers, pull-out drawers, drawer dividers, etc.) are matched on relevance only, never forced through a rigid min/max size check. No price data exists in the source sheet, so price is dropped from the UI entirely rather than guessed — "View on Amazon" only. Links are rebuilt as `amazon.com/dp/{ASIN}` from the real ASINs (the sheet's own links used a placeholder `link.amazon` domain).

## TBD

- **Captcha runs on Cloudflare's test key, not the real one** — the real Turnstile site key fails immediately with a domain-mismatch error (see README's "Local dev domain limitation") because the captcha page is inline HTML in a WebView with no real hostname for Cloudflare to validate against `localhost` or any other registered domain. `.env` currently holds Cloudflare's official "always passes" test pair so signup/login work end-to-end during development. **Before shipping**, this needs either a real production domain registered with Turnstile, or the captcha page moved to an actual backend route the WebView loads by URL (so there's a real domain to register) — otherwise every real signup/login will fail the same way local testing did.
- **Onboarding re-view** — the onboarding screen is currently one-shot (shown once after signup, never again). If it turns out people want to revisit it, the simplest addition is a link from the Welcome screen — not built now since only Home/Projects tabs were wanted as persistent nav.
- **`/report/email` recipient isn't authorization-gated beyond a valid session_id** — consistent with how every other session-scoped endpoint in this app already works (no per-endpoint ownership check beyond knowing the session id), but worth knowing: anyone who can guess/observe a session_id could trigger one email send to an address of their choosing. Low risk today (session ids are UUIDs, not guessable), but flagging since it's a real difference from a fully user-authenticated send.
- **Final report still needs work** — flagged directly by testing: the current structure (collapsible AI-generated sections) isn't landing as professional/polished enough yet. **Blocked on a mockup from Natasha** showing the structure/format she actually wants — implementing further redesign without one risks guessing wrong again.
- **Amazon product catalog — resolved.** Real per-product links now exist (see "Shipped this round" above) — this is no longer blocked. Still open: no price data was in the source sheet, so no price shows anywhere in the app; if a price list ever gets provided, it can be added to each `PRODUCTS` entry in `products.py` and wired back into `ProductCard.js`/`format_products_summary`.
- **Real AR/hardware measuring** — out of scope so far. The existing ARKit hook (`native/ARMeasurementModule.ts`) is still wired in as an optional shortcut on real iOS hardware.
- **Free/paid tier feature gating** — only the voice differs today (Natasha vs. neutral). What's actually gated (room limits, report limits, chat depth, etc.) is still a decision pending.
- **Exact mid-step resume** — resuming restores which rooms/areas are already organized, but not the exact step you were on mid-flow (e.g. mid-photo-capture). Full state-machine rehydration is a larger, separate feature.
- **Email deliverability** — report emailing is now live via plain Gmail SMTP (chosen explicitly over a transactional provider). Gmail SMTP has a ~500/day send cap and no SPF/DKIM alignment for a custom domain, so some recipients' spam filters may catch it. Worth upgrading to a transactional provider (SendGrid/Postmark/Resend/SES) if delivery becomes unreliable at real volume.
